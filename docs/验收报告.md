## 二、负向用例（应拦截场景）

| 编号 | 构造场景 | 期望 | 实测 | 结果 |
|---|---|---|---|---|
| N1 | 申请单声明 27,000,000 元 vs 合同价税合计 30,510,000 元 | fail / check_amount | fail / 金额一致性 fail | ✅ |
| N2 | 申请单抬头写简称「广州粤海智能装备（简称）」 | fail / check_title | fail / 抬头一致性 fail | ✅ |
| N3 | 合同税率由 13% 篡改为 9%（税额同步重算） | fail / check_tax_rate | fail / 税率正确性 fail | ✅ |
| N4 | 验收金额改为合同不含税的 80%（部分验收） | fail / check_amount | fail / 金额一致性 fail | ✅ |
| N5 | 同一业务重复提交（会话发票池已存在同客户同金额发票） | fail / check_duplicate | fail / 重复开票 fail | ✅ |
| N6 | 移除验收单，仅留合同 + 出库单 | suspend / check_date | suspend / 日期合理性 suspend | ✅ |

设计要点：**「证据冲突」判不通过（fail），「证据缺失」判暂缓（suspend，等待人工补充）**，两者在界面与日志中区分展示，避免把「单据没传」误报成「业务违规」。

## 四、数据质量与口径发现

> 全部由 `tools/data_quality.py` 从数据实跑得出，可复现。已内联进应用「验收指标」视图。

**台账与原件金额对账：175/175 一致，异常 0 条，解析告警 0 条。**
对账口径（不同单据金额含义不同）：发票/合同取价税合计，验收单/到货签收单取明细金额合计（不含税），出库单取成本金额合计，海关缴款书取进口增值税。

1. **唯一一处台账与原件不一致（信息级）**：`WS-202512-001` 海关进口增值税专用缴款书，台账「对方单位」记「上海海关」，原件记载境外发货人 `DECKEL MAHO GMBH`。属登记口径差异、非解析错误；该单据为进项抵扣凭据，不参与销项开票审核。这也是「关键字段提取 99.86%」的唯一扣分点。
2. **43 张发票购买方纳税人识别号缺失**：原件该栏为「—」（出口发票 2 张 + 增值税普通发票 41 张）。审核引擎将其降级为「提示」而非不通过——数据缺失不等于业务错误，界面明确提示需人工补充。
3. **费用类普通发票征收率超出字典**：40 张 3%、2 张 6%；`tax_rates` 字典按 Prompt 要求固定 13%/9%/6%/0%/5%。3% 属小规模纳税人简易计税征收率，未擅自扩字典，而是在审核中不按销项税率校验并标注「需人工复核」。
4. **42 张普通发票「税额 = 金额×征收率」不勾稽**（差额 0.09–0.5 元）：原件按价税合计倒算时未取整到分（如 777.00×3%=23.31，原件 23.00）。已作为数据发现记录，不影响销项审核判定。
5. **22 张验收单「物料/产品」列填的是单据名称「设备安装验收单」**，不是产品名。因此验收证据匹配必须用「对方单位 + 不含税金额 + 数量」三元组；否则越南 HMC 的「2 台 / 1 套」两单（同客户、同金额 6,000,000）会互相错配。
6. **关键业务数据表与销售明细口径冲突**：「待开票事项 2 项」vs 销售明细 22 行 vs 参照系统 KPI 22。本应用统一采用 **22 项**；「2」实际对应未验收暂缓的 2 台设备（合同 HT-202512-002），已作为独立提示展示，两者不混用。
7. **未验收暂缓事项（教学考点）**：合同 HT-202512-002（价税合计 10,170,000.00 元，2 台）只有到货签收单 `YS-202512-002`、无验收单 → 控制权未转移 → 暂缓开票。该情形不计入销售明细 22 行（销售明细注明「未验收 2 台不计入」），以独立用例 TC-022 覆盖。
8. **数据集内已含 22 项业务的「已开具发票」**（104 张发票中销项部分与 22 项待开票事项一一对应）。这些发票被界定为「标准答案/历史样本」而非本次开票证据：装配申请时默认排除发票类单据；重复开票校验默认使用**本会话发票池**，命中历史池时降级为提示并说明可能为对照样本。若误把历史发票放进证据链，会把「已开过票」误判成「重复开票」。

## 五、与 Prompt 文档的差异与未完成项（如实说明）

| 项 | Prompt 要求 | 实际处理 | 原因 |
|---|---|---|---|
| 后端服务 | MySQL 15 张表 + Node 代理 + `start.bat` 一键启动 | 未实现后端；客户档案仅取数据集内可得信息，信用等级等标注「未提供（需对接 customers 表）」 | 与架构II「无需安装依赖、无需启动服务器、双击即开」直接冲突；已按用户确认以架构II 为准。**未编造任何数据库数据** |
| 大模型调用 | Finance AI `deepseek-v4.1-flash` 真实调用 | 实现完整配置界面与调用代码，含失败自动降级；**未接真实密钥，未做真实联调** | 无可用密钥/代理地址；`file://` 下跨域请求会被浏览器拦截，需本地代理 |
| OCR | 图片/PDF 走 OCR | 未内置 OCR 引擎；图片/PDF 明确提示「需人工补充」 | 纯前端离线环境无 OCR 能力，且不允许联网安装依赖 |
| 数电票 XML | 支持 | 未实现解析 | 数据集未提供 XML 样本，无样本可验证，不臆造格式 |
| XLSX 上传 | 支持 | 数据集单据均为 HTML，上传解析覆盖 HTML/JSON；XLSX 需第三方库 | 无外部依赖约束下无法解析 xlsx 二进制 |

**未验证项（不得视为通过）**：
- 视觉/排版未经人眼验收。本机无视觉模型，已用 DOM 度量替代（1600 宽无横向溢出、9 个视图内容区尺寸正常、样式表确认生效），最终外观需用户目视确认。
- 1366×768 小屏实测、真机性能、`file://` 下 `localStorage` 可用性（已 try/catch 降级）。
- 大模型真实返回内容的质量。

**安全边界（须知）**：
- 交付包 Prompt 文档中的 MySQL 连接串与口令（`readonly_user` / `StrongPass123!`）**未写入** `index.html` 或任何源码/数据文件（已用全文检索确认 0 命中），前端不存任何数据库凭据。
- 大模型 API Key 为用户在界面自行填写，仅保存在本机浏览器 `localStorage`（纯前端无法加密隔离）。共用电脑请用完清除；正式环境应改为后端代理持有密钥。
